# ShopFlow

واجهة عربية RTL لإدارة المتجر، مع تسجيل حسابات وتجربة مجانية مدتها 48 ساعة تبدأ فقط عندما يضغط المستخدم على زر البدء.

## التشغيل المحلي

```bash
npm install
cp .env.example .env
npm run dev
```

أضف بيانات مشروع Supabase إلى ملف `.env`:
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

## إعداد Supabase

1. أنشئ مشروعًا في Supabase.
2. افتح SQL Editor.
3. نفّذ محتوى الملف `supabase/schema.sql`.
4. من Authentication > Providers فعّل Email.
5. أضف متغيري البيئة السابقين في Vercel لكل من Production وPreview وDevelopment.

## منطق التجربة

- يبدأ الوقت عند أول استدعاء ناجح لـ `start_my_trial()` بعد ضغط المستخدم.
- قيد المفتاح الأساسي `user_id` يمنع إنشاء تجربة ثانية للحساب نفسه.
- وقت البداية محفوظ في قاعدة البيانات، لذلك لا يتغير بتسجيل الخروج أو الدخول.
- انتهاء الصلاحية يُحسب من وقت البداية + 48 ساعة.

## النشر على Vercel

المشروع مبني باستخدام Vite. اربط مستودع GitHub هذا في Vercel، وسيتم اكتشاف إعدادات Vite تلقائيًا. أضف متغيرات Supabase قبل إتمام النشر.


## إعداد الأنشطة وبيانات المنصة

بعد تشغيل إعدادات المتجر الأساسية، نفّذ ملف `supabase/shopflow-platform.sql` من Supabase SQL Editor. يضيف نوع النشاط وجداول المنتجات والعملاء والطلبات وصفحات الموقع والتكاملات وفريق العمل والحجوزات، مع سياسات RLS لعزل بيانات كل حساب.

الأنشطة المدعومة في الإعداد الأولي: متجر عام، مطعم وكافيه، ملابس وأزياء، إلكترونيات، تجميل وعناية، وخدمات وحجوزات.

> ملاحظة: هذا الملف يجهز طبقة قاعدة البيانات. بعض الأقسام الظاهرة في الواجهة هي نقاط تأسيسية وليست تكاملات تشغيلية مكتملة بعد. لا تخزن مفاتيح الدفع أو الشحن السرية في جداول عامة أو في متغيرات تبدأ بـ `VITE_`.

## إصلاح وصول رمز OTP بالبريد

Vercel يستضيف الواجهة فقط. رسائل تأكيد الحساب يرسلها Supabase Auth أو مزود SMTP الذي تضبطه داخل Supabase. وجود متغيرات Supabase في Vercel لا يضبط خدمة إرسال البريد.

1. في Supabase افتح **Authentication → Providers → Email** وتأكد أن Email provider مفعّل وأن إعداد تأكيد البريد مناسب للتسجيل برمز.
2. افتح **Authentication → URL Configuration** واجعل Site URL هو رابط الإنتاج الفعلي، وأضف رابط الإنتاج وأي رابط Preview تستخدمه إلى Redirect URLs. مثال الإنتاج الحالي: `https://shopflow-codex-7d26.vercel.app/**`.
3. افتح **Authentication → Email Templates → Confirm signup**. إذا كنت تستخدم شاشة إدخال رمز من 6 أرقام، يجب أن يحتوي قالب التأكيد على متغير الرمز `{{ .Token }}` بشكل واضح؛ قالب رابط الدخول وحده لن يعرض الرمز المطلوب للمستخدم.
4. للاستخدام الحقيقي، أعد إعداد SMTP مخصص من مزود بريد موثوق (مثلاً Resend أو Postmark أو SendGrid) داخل **Project Settings → Authentication → SMTP Settings** أو إعداد SMTP في صفحة Auth حسب واجهة لوحة Supabase الحالية. أكمل توثيق نطاق المرسل وDNS لدى مزود البريد، واضبط عنوان From على نطاق موثق.
5. جرّب التسجيل ببريد تملكه، وافحص Inbox وSpam، ثم راجع سجلات Auth ورسائل SMTP لدى المزود إذا لم تصل الرسالة.

خدمة البريد الافتراضية في Supabase مخصصة للاختبار ومحدودة؛ لا يمكن ضمان تسليم البريد إلى صناديق المستخدمين دون إعداد SMTP مناسب. لا تضع SMTP password أو مفاتيح مزود البريد في الواجهة أو GitHub أو متغيرات `VITE_`. أدخلها مباشرة في لوحة مزود الخدمة/Supabase. لا تشاركها في المحادثة.

## إعداد Vercel

تأكد من وجود `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` في Production. أضفهما أيضاً إلى Preview وDevelopment إذا كنت ستختبر تلك البيئات. لا تستخدم `service_role` في الواجهة الأمامية.
